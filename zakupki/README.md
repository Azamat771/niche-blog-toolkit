# Анализатор несостоявшихся закупок

Инструмент ищет госзакупки, **на которые никто не подал заявку**, и отвечает на
вопрос: в какие ниши можно зайти новому поставщику, где нет конкурентов.

Считает по открытым данным ЕИС (zakupki.gov.ru): выкачивает XML-архивы,
определяет исход каждой закупки, склеивает переобъявления одной и той же
потребности в цепочки и строит рейтинг ниш.

> Живёт в этом репозитории как отдельный модуль и с Instagram-тулкитом никак не
> связан: у него свои зависимости (их нет — только Node), свой CLI и свои данные.

## Быстрый старт

```bash
# 1. Убедиться, что всё работает — на синтетических данных, без сети
node zakupki/cli.js demo
node zakupki/cli.js selftest

# 2. Скачать реальные данные по Оренбургской области за 6 лет
node zakupki/cli.js fetch --region=Оренбургская --from=2021-01 --to=2026-08

# 3. Разобрать и построить отчёт под бюджет до 600 тыс ₽
node zakupki/cli.js analyze --budget-max=600000
```

Результат — в `zakupki/out/`:

| Файл | Что внутри |
| --- | --- |
| `report.md` | Отчёт: динамика по годам, рейтинг ниш, конкретные точки входа |
| `niches.csv` | Все ниши со счётчиками — для сводных таблиц в Excel |
| `opportunities.csv` | Закупки, где последняя попытка провалилась без заявок |
| `purchases.csv` | Все закупки построчно, с фрагментом-доказательством исхода |

Требуется только Node.js 18+. Внешних зависимостей нет.

## Если `fetch` не находит данные

Структура каталогов на FTP ЕИС менялась между редакциями, поэтому пути не
зашиты жёстко — клиент обходит дерево и ищет каталог региона сам. Если поиск
не сработал, посмотрите реальную структуру:

```bash
node zakupki/cli.js explore --law=44 --depth=2
node zakupki/cli.js explore --region=Оренбургская --law=44 --depth=3
```

и укажите корень явно:

```bash
node zakupki/cli.js fetch --region=Оренбургская --root=/fcs_regions --from=2021-01 --to=2026-08
```

Разбор данных не завязан на загрузку. Если архивы удобнее скачать вручную
(FileZilla, браузер, wget) — положите их куда угодно и укажите каталог:

```bash
node zakupki/cli.js parse --dir=~/Downloads/zakupki
node zakupki/cli.js analyze --budget-max=600000
```

Чтобы 44-ФЗ и 223-ФЗ не смешались, раскладывайте архивы по подпапкам
`fz44/` и `fz223/` — по ним определяется закон.

## Как читается отчёт

**Раздел 1 — охват.** Сколько документов разобрано и по скольким закупкам исход
остался неизвестным. Если неизвестных больше 30%, отчёт сам об этом
предупредит: обычно это значит, что выгружены извещения, но не протоколы, и
доля «нет заявок» занижена.

**Раздел 2 — динамика.** Две таблицы: полные годы и YTD-срез. Второй важнее:
текущий год ещё не кончился, и сравнивать его с целыми прошлыми годами
бессмысленно, поэтому у всех лет берётся одинаковое окно январь–текущий месяц.

**Раздел 3 — рейтинг ниш.** Score 0–100:

| Вклад | Вес | Смысл |
| --- | --- | --- |
| Доля закупок без заявок | 35 | Главный признак пустой ниши |
| Среднее число переобъявлений | 20 | Заказчик не сдаётся — потребность реальная |
| Объём закупок | 15 | Разовая закупка ≠ рынок |
| Число разных заказчиков | 10 | Не завязано на одного клиента |
| Повторяемость по годам | 10 | Спрос вернётся в следующем году |
| Динамика текущего года | 10 | Ниша растёт, а не умирает |

**Раздел 4 — точки входа.** Самое практичное. Конкретные заказчики с предметом
закупки, НМЦК, числом провалов и месяцами, в которые они обычно объявляют.
Столбец «Обычные месяцы» подсказывает, когда готовить документы к следующей
волне.

## Параметры

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--region=` | — | Регион, обязателен для `fetch`/`explore` |
| `--law=44,223` | оба | Какие законы анализировать |
| `--from=` / `--to=` | весь период | Границы выгрузки, формат `YYYY-MM` |
| `--budget-max=` | 600000 | Потолок НМЦК |
| `--budget-min=` | 0 | Нижняя граница НМЦК |
| `--min-count=` | 4 | Минимум закупок, чтобы ниша попала в рейтинг |
| `--fresh-months=` | 12 | Глубина «свежих» точек входа |
| `--date=` | сегодня | Дата расчёта — задаёт окно YTD-сравнения |
| `--dir=` | `zakupki/data` | Каталог с архивами для `parse` |
| `--secure` | выкл | FTPS вместо обычного FTP |
| `--verbose` | выкл | Подробный лог, включая ошибки обхода |

## Что важно понимать про выводы

Инструмент показывает, **где не было конкурентов раньше**. Это не гарантия, что
их не будет в следующий раз, и не гарантия, что вы сможете исполнить контракт.

Ниша может пустовать по причинам, которых не видно в цифрах:

- нужна лицензия, допуск СРО, членство в реестре или аккредитация;
- НМЦК посчитана ниже рынка, и работать по ней невыгодно;
- нереальные сроки поставки или неудобная логистика в район;
- у заказчика репутация неплательщика;
- требования документации написаны под конкретного поставщика.

Поэтому раздел 4 — это список для **проверки документации**, а не список
гарантированных контрактов. Перед подачей заявки открывайте извещение в ЕИС по
ссылке из отчёта и читайте требования.

Отдельно: исход закупки определяется по формулировкам в протоколах, а не по
жёсткой схеме — схемы ЕИС менялись год от года. В `purchases.csv` для каждой
закупки лежит фрагмент текста, по которому принято решение; если какая-то ниша
выглядит подозрительно хорошо, проверьте по нему несколько строк.

## Как устроено

```
zakupki/
├── cli.js              команды: explore / fetch / parse / analyze / demo / selftest
├── src/
│   ├── ftp.js          FTP/FTPS-клиент на net+tls
│   ├── zip.js          чтение ZIP через zlib (deflate, stored, ZIP64)
│   ├── xml.js          терпимый XML-парсер без привязки к XSD
│   ├── extract.js      XML → плоские записи
│   ├── classify.js     определение исхода по маркерам + доказательства
│   ├── taxonomy.js     ниши: разделы ОКПД2 + ключевые слова для 223-ФЗ
│   ├── cluster.js      склейка переобъявлений в цепочки
│   ├── analyze.js      агрегация, YTD-сравнение, скоринг
│   ├── report.js       markdown + CSV
│   └── ingest.js       разбор локальных архивов
└── test/               офлайн-тесты и генератор демо-данных
```

Всё написано на встроенных модулях Node — ставить нечего, работает офлайн после
выгрузки.
